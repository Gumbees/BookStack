# Wiki Links and Backlinks

## Wiki-link typeahead

Typing `[[` in either editor triggers a typeahead dropdown to search for and link to any page, book, or chapter.

### How it works

1. Type `[[` in the Markdown or WYSIWYG editor
2. Continue typing a search term
3. A dropdown appears with matching results (debounced 200ms search)
4. Use arrow keys to navigate, Enter to confirm, Escape to dismiss
5. The selected entity is inserted as a Markdown link or Lexical link node

The search hits `GET /search/entity-selector?types=page,book,chapter&permission=view&term=...` and returns up to 8 results.

### Link format

Pages are inserted using their permalink (`/link/{id}`). This means the link remains valid even after a page is moved or renamed. Books and chapters use their regular URL.

For example, typing `[[my page]]` and selecting "My Page" inserts:

```markdown
[My Page](https://example.com/link/42)
```

### Keyboard navigation

| Key | Action |
|-----|--------|
| `ArrowDown` | Move selection down |
| `ArrowUp` | Move selection up |
| `Enter` | Confirm selected item |
| `Escape` | Dismiss dropdown |

### Editor support

Both editors implement the feature independently:

- **Markdown editor** ... `resources/js/markdown/wiki-links.ts` hooks into the CodeMirror `input` event
- **WYSIWYG editor (Lexical)** ... `resources/js/wysiwyg/services/wiki-links.ts` listens on `CHANGE_COMMAND` and monitors `TextNode` changes

## Backlinks sidebar

The backlinks sidebar shows which other pages or entities reference the current entity. It appears as a collapsible panel on the page view and is loaded asynchronously.

### Linked mentions

"Linked" items are entities that contain a tracked reference link (a cross-link in the `references` table) pointing to the current entity. These are stored when content is saved and are reliable.

### Unlinked mentions

"Unlinked" items are pages whose plain-text content contains the entity's name but don't have a tracked reference link. These are found via a full-text `LIKE` search. Up to 10 results are returned for each category.

### References table

The `references` table stores cross-links between entities. It is populated by `ReferenceUpdater` whenever a page, chapter, book, or shelf is saved. The `CrossLinkParser` extracts `href` values from the HTML content and resolves them to entity IDs via the model resolvers in `app/References/ModelResolvers/`.

Pages resolved via `/link/{id}` permalinks are handled by `PagePermalinkModelResolver`. Direct slug-based URLs are handled by the type-specific resolvers.

## Permalink format

Every page has a stable permalink at:

```
/link/{pageId}
```

This redirects to the current page URL regardless of the page's slug or book. Links generated by the wiki-link typeahead always use this format for pages, so they survive page renames and moves.

## API endpoint

```
GET api/{type}/{id}/backlinks
```

Valid `type` values: `page`, `chapter`, `book`, `shelf`.

Response:

```json
{
  "linked": [
    {
      "id": 10,
      "type": "page",
      "name": "Another Page",
      "url": "https://example.com/books/my-book/page/another-page",
      "excerpt": "...contains a link to <mark>My Page</mark>..."
    }
  ],
  "unlinked": [
    {
      "id": 15,
      "type": "page",
      "name": "Some Other Page",
      "url": "https://example.com/books/other-book/page/some-other-page",
      "excerpt": "...mentions My Page in passing..."
    }
  ],
  "linked_count": 1,
  "unlinked_count": 1
}
```

The web (non-API) version is available at `GET /ajax/backlinks/{type}/{id}` and includes a `breadcrumb` field used by the sidebar UI.
